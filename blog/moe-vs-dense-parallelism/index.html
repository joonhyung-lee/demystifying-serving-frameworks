Dense Model: TP Only (Llama 70B)

For a dense model like Llama 70B on 4 GPUs with TP=4, every layer is sharded identically. The only collective operation needed is AllReduce — and it happens at the same points in every layer:

Dense TP is simple: every layer uses the same pattern — shard weights, compute partial results, AllReduce. No routing, no token movement between GPUs. The only cost is the AllReduce bandwidth, which scales with hidden size.

MoE Model: EP OFF (gpt-oss-120b)

With EP disabled and DP=4, vLLM uses the DP ranks as extra TP ranks for the MoE layer. Each GPU holds all 128 experts but with weights sharded along the intermediate dimension (flatten_tp_size = dp × tp). This requires:

  1. AllGather — replicate all tokens from all DP ranks to every GPU
  2. Local compute — each GPU runs top-4 routing on its sharded expert weights
  3. ReduceScatter — sum partial results and scatter back to owner ranks

EP OFF trade-off: every GPU holds all experts (high memory), but the communication is regular (AllGather + ReduceScatter). The sparse routing is not exploited — all tokens are replicated to all GPUs regardless of which expert they need.

MoE Model: EP ON (gpt-oss-120b)

Collective Operations Reference

Four collective operations appear in the dataflows above. Here is what each one does:

AllReduce
Each rank holds a partial result. The operation (typically sum) is applied element-wise across all ranks, and every rank receives the same final result.
Used in: TP — after every attention output projection and FFN down projection.
AllGather
Each rank holds its own chunk. After AllGather, every rank has the concatenation of all chunks.
Used in: MoE EP OFF — before the MoE layer, to replicate all DP ranks' tokens to every GPU so they can all compute on the full token set.
ReduceScatter
Each rank holds the full data. The operation is applied element-wise, and each rank receives only its own reduced portion.
Used in: MoE EP OFF — after the MoE layer, to sum partial expert outputs and scatter each rank's portion back.
All-to-All
Each rank sends different data to each other rank. Rank i's j-th chunk goes to rank j. This is point-to-point, irregular communication.
Used in: MoE EP ON — dispatch (send tokens to expert-owner GPU) and combine (return results to source GPU).

The fundamental insight: Dense models only need AllReduce (symmetric, predictable). MoE models introduce a new dimension — EP OFF trades memory for regular communication (AllGather + ReduceScatter), while EP ON trades regular communication for sparse, point-to-point All-to-All that exploits expert sparsity but is harder to overlap with compute.
